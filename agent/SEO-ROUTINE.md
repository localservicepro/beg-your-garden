# Monthly SEO research routine

This file is the playbook for the scheduled Claude Routine that keeps begyourgarden.com aligned with live search
demand. A fresh session runs it every month. Read it fully before touching anything.

## What the site is

Static site generated by `npm run build` from `src/`. Content lives in data files, not templates:

| File | What it controls |
|---|---|
| `src/data/site.js` | business facts, services (titles, metas, H1s, FAQs), home FAQs, reviews, gallery |
| `src/data/areas.js` | suburb landing pages (`/lawn-mowing-{slug}/`) |
| `src/data/blog.js` | blog posts (`/blog/{slug}/`) |
| `src/data/keywords.json` | the research record this routine reads and updates |
| `README.md` | documents the data sources; update its tables when pages are added |

`npm run build && npm run check` must pass before anything is pushed. `check` enforces one H1, title ≤ 60
chars, description ≤ 160 chars, alt text, valid JSON-LD, the tracking script, and homepage keyword density.

## Data sources (MCP connectors)

- **DataForSEO**: `kw_data_google_ads_search_volume` (location "Australia", language "en"; it returns at most 10
  keywords per call, so batch in tens), `dataforseo_labs_bulk_keyword_difficulty`, `dataforseo_labs_google_related_keywords`,
  `serp_organic_live_advanced` for where begyourgarden.com ranks on the money keywords.
- **Ubersuggest**: `keyword_suggestions` / `keyword_overview` with `locId` 2036 (Australia) as a cross-check.
- **RankTitan**: `list_businesses` then `get_keyword_rankings` / `get_local_heatmap` for map-pack rankings, if the
  Beg Your Garden profile is set up there. Local Falcon is not connected yet; skip it without failing.
- Google Search Console is not connected. Do not invent click or impression data.

## Steps

1. `git fetch origin main && git checkout -B seo/research-YYYY-MM origin/main` (today's year-month).
2. Re-pull volume and difficulty for every keyword in `keywords.json` (money keywords, suburbs, blog topics) and
   for `lawn mowing {suburb}` across all 84 suburbs in `src/data/site.js`. Append this month to each `history`
   and update `volume` / `difficulty`. Pull current organic position for the money keywords and record it under
   `rankings` with the date.
3. Decide, using `thresholds` in `keywords.json`:
   - **New suburb page** when a suburb with `page: null` has volume ≥ `new_suburb_page_min_volume` for
     ≥ `new_suburb_page_min_months` consecutive months (history entries). Write it in `src/data/areas.js`
     following the existing entries exactly: unique local copy about that suburb's housing and lawns, 3–4 FAQs,
     a real review only if one exists for that suburb (the `reviews` array), image from `src/public/images/`.
   - **New blog post** when an informational keyword has volume ≥ `new_blog_min_volume` and difficulty ≤
     `new_blog_max_difficulty` and no post covers it. Write it in `src/data/blog.js` in the same shape as the
     existing posts: Queensland-specific, 600–900 words, 4 FAQs, a callout linking the matching service.
   - **Meta rewrite** for an existing page only when its keyword's volume has shifted meaningfully or a higher
     volume phrasing has emerged. Keep the approved H1s on `/`, `/about/` and the six service pages unchanged.
   - Respect `max_new_pages_per_run`, `max_new_posts_per_run`, `max_meta_rewrites_per_run`.
4. Never write claims the client has not supplied. No equipment brands, no "battery", "quiet", "fume" or
   noise claims, no prices beyond the labelled market guide in the cost post, no invented route days
   (only Raceview = Wednesday and Ripley = Friday are known).
5. Add a line to `keywords.json` → `log` describing what changed and why, with the numbers.
6. `npm run build && npm run check`. Fix anything that fails.
7. Commit (one commit, clear message), push the branch, and open a **draft pull request** against `main` titled
   `SEO research YYYY-MM` whose body lists: keywords that moved (old → new volume), pages added, metas changed,
   suburbs now close to threshold, and anything that needs a human decision. If no change is warranted, still
   push the updated `keywords.json` and open the PR so the record stays current.

Do not merge. Do not push to `main`. Do not touch design files, templates, images or the tracking script.
